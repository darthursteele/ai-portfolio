# Agentic AI Framework

A production-ready multi-agent development environment built on [CrewAI](https://github.com/joaomdmoura/crewai).

## Origin

This framework wasn't hand-scaffolded. It was generated by [`/prompts/crewai_repo_prompt.md`](../prompts/crewai_repo_prompt.md) — a meta-prompt that takes a project name and a few configuration flags, then outputs a complete production-ready CrewAI repository: directory structure, base classes, configuration management, structured logging, Docker, CI/CD, and working example crews.

It's a useful illustration of prompts-as-tools: instead of building boilerplate manually, engineer a prompt that does it reliably and reuse it across projects.

## What's Implemented

Three working crew types, a factory pattern for managing them, performance monitoring, and a CLI orchestrator:

**Research Crew** — multi-agent information gathering and synthesis. A researcher with web search access hands off to a writer who produces structured output.

**Content Analysis Crew** — three agents in sequence: content analyst extracts themes and sentiment, data scientist quantifies the analysis, report writer packages findings into a deliverable.

**Creative Writing Crew** — story planner → writer → editor pipeline. Each stage builds on the prior agent's output.

Two additional crew types (`data_analysis`, `social_media`) are defined but not yet implemented — placeholders for future expansion.

## Getting Started

```bash
# Install dependencies
pip install -r requirements.txt

# Copy environment template
cp ../.env.example .env
# Add your OPENAI_API_KEY and SERPER_API_KEY to .env

# List available crews
python main.py --list-crews

# Run a crew
python main.py --crew research --topic "AI product management trends 2025"
python main.py --crew content_analysis --content-file path/to/file.txt
python main.py --crew creative_writing --story-prompt "A PM who discovers their roadmap is sentient"

# Development commands
make help       # all available commands
make test       # run test suite
make lint       # linting + type checking

# Docker
docker-compose up -d
```

## Design Decisions

**Factory pattern for crews.** The `CrewFactory` class centralizes crew creation and configuration, making it easy to add new crew types without modifying the orchestrator. Config overrides flow down from the CLI to individual agent settings.

**Async support.** `run_crew_async` runs crews in a thread pool executor, enabling non-blocking execution in async contexts without requiring CrewAI to be async-native.

**Performance monitoring.** Every crew execution is instrumented: start time, completion time, task count, agent count. The `PerformanceMonitor` collects global metrics across runs, useful for understanding cost and latency at scale.

**Structured logging.** JSON-formatted logs with crew execution context baked in. Separate log levels for dev (verbose) and prod (structured only).
